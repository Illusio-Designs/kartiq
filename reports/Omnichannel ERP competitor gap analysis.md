# Kartriq should rebuild Flipkart, Myntra and Meesho first

Kartriq's strongest asset, the Amazon Confirm, label and shipment-status flow, appears to be rare among the competitors checked, but the gap that matters most sits elsewhere: the Flipkart, Meesho and Myntra adapters, which cover only orders and inventory, were written without official docs and have never run live. Flipkart is the only one of the three with a public, self-serve developer API, and its v3 Order Management API exposes label, dispatch (ready-to-dispatch, RTD) and manifest calls that Kartriq can build against now. Myntra has an official developer centre, but the real credentials (Merchant Id, Secret Key, Warehouse Id) differ from Kartriq's assumed supplierId/apiKey/secretKey, and "omnishipper" returned no hits anywhere. Meesho has no public documentation found; access is by emailing its integration team, and Kartriq's assumed host and header look unsupported. Incumbents such as Unicommerce, Vinculum and EasyEcom win on marketplace depth (Myntra, Ajio, Nykaa, Tata CLiQ, JioMart) and on GST, Tally and reconciliation tooling that Kartriq lacks. Global tools (Zoho, Linnworks, Cin7, Extensiv, Brightpearl, Rithum) add rate shopping, SKU profitability and costing, but none of their Amazon-arranged-label behaviour could be confirmed. **Evidence quality is weak throughout:** researchers could not open most vendor or marketplace pages, so nearly everything below rests on search summaries and vendor help articles, and no endpoint was tested. The recommended order is: verify credentials and docs, rebuild Flipkart, then Myntra, then Meesho, then add GST/e-invoice, Tally and reconciliation features.

## Evidence is thin, so treat every claim by its grade

The research notes disclose that fetches of seller.flipkart.com, shopify.dev, mmip.myntrainfo.com, documentation.fynd.com and most vendor domains failed (DNS errors or proxy policy blocks), so no official page was read in full. Three grades apply in this report. **Secondary** means the claim comes from a search summary of an official page, or from an OMS vendor's help article describing a marketplace connection; this covers the Flipkart endpoint list, Myntra PPMP V4 rules and all vendor feature claims. **Unofficial** means a single third-party directory or review site. **Unknown** means nothing was found. Nothing was verified on a live account or against a sandbox. Two consequences follow. Endpoint paths quoted below are leads for a developer to confirm, not specifications, and field-level request and response shapes are unverified for every marketplace. And vendor claims such as connector counts are marketing figures: Unicommerce says 285+ integrations and 7,500+ clients ([GetApp](https://www.getapp.com/all-software/a/unicommerce/)), EasyEcom 200+ ([EasyEcom](https://easyecom.io/whatsnew-articles/easyecom-launches-100-global-shipping-integrations)), Vinculum 150+ while Capterra lists only 11 ([Capterra](https://www.capterra.ie/reviews/152554/vin-eretail-wms)), and Increff 50+ ([Increff](https://www.increff.com/omni-solution)). No source gave a per-marketplace matrix separating orders-only connectors from full dispatch, label and returns support, so "listed" must not be read as "full lifecycle".

## Flipkart is the only fulfilment API Kartriq can build against today

Flipkart publishes a Developer API v3.0 at seller.flipkart.com/api-docs, and access is self-serve: the seller creates an application under Manage Profile, Developer Access and receives an Application ID and Secret ([Flipkart docs](https://seller.flipkart.com/api-docs/FMSAPI.html)), corroborated by OMS help pages ([Browntape](https://help.browntape.com/support/solutions/articles/33000265698-how-to-get-flipkart-api-details-manually-)). Authentication is an OAuth2 client-credentials grant with scope `Seller_Api`, production host api.flipkart.net, sandbox host sandbox-api.flipkart.net, and a token lifetime "usually 60 days" ([Flipkart FAQ](https://www.seller.flipkart.com/api-docs/_sources/FAQ.rst.txt)). Because credentials are per seller, a multi-tenant product has each tenant paste its own Application ID, Secret and location ID (an inference; EasyEcom's setup works this way, also asking for seller ID, which it says is read from browser dev tools ([EasyEcom](https://support.easyecom.io/portal/en/kb/articles/steps-to-integrate-you-easyecom-account-with-flipkart))). The sandbox is not automatic: the FAQ says registration alone does not grant it and a support ticket is required, so a developer should raise that ticket immediately.

The order model is shipment-centric, with two documented workflows, Standard Fulfilment (Flipkart logistics) and Self Ship ([Flipkart OM overview](https://seller.flipkart.com/api-docs/order-api-docs/OMAPIOverview.html)). The reference pages, as summarised by search, list the calls Kartriq needs ([OM reference](https://seller.flipkart.com/api-docs/order-api-docs/OMAPIRef.html)):

| Step | Reported call (secondary, shapes unverified) |
|---|---|
| Find shipments | `POST /v3/shipments/filter/` (page size 1-20, 5,000 max retrievable; post-dispatch must be queried separately for SELF and NORMAL) ([ref](https://seller.flipkart.com/api-docs/order-api-docs/v3/PostShipmentSearch.html)) |
| Shipment details | `GET /sellers/v3/shipments?shipmentIds=` (includes dispatch-by date) |
| Pack and label | `POST /v3/shipments/labels` moves shipments to Packed and generates label and invoice; `GET /v3/shipments/{ids}/labels` downloads it |
| Dispatch (RTD) | `POST /v3/shipments/dispatch` with shipment IDs and location ID |
| Cancel | `POST /v3/shipments/cancel` with an enumerated reason; cancellations zero the listing and repeated ones risk seller deactivation |
| Manifest and handover | `POST /v3/shipments/manifest`; `GET /v3/shipments/handover/counts?locationId=` |
| Events | A notifications service exists (for example READY_TO_DISPATCH) ([ref](https://seller.flipkart.com/api-docs/order-api-docs/NotifRef.html)) |
| Inventory | `POST /listings/v3/update/inventory`, batch of 10, per-location ([ref](https://seller.flipkart.com/api-docs/listing-api-docs/v3/UpdateListingsInventoryAPI.html)) |

The implied flow is filter, labels (which doubles as pack), label download, dispatch, then manifest and handover; there is no separate "confirm" call, and no seller tracking-update endpoint was found. The notes record a conflict: an older inventory tutorial uses a different `stock_count` format than the v3 reference ([tutorial](https://seller.flipkart.com/api-docs/listing-api-docs/InventoryTut.html)), so the current reference must win. Unknowns that block a design: rate limits (no figures found), Self Ship tracking-number submission, and any returns or RTO endpoints. Smart Fulfilment (Flipkart-warehoused stock) has no public API for third-party warehouse systems according to Increff, which also says Smart was discontinued on 1 August 2022 and that Seller Fulfilment uses the standard seller APIs ([Increff](https://support.increff.com/support/solutions/articles/36000320509-flipkart-dropship-seller-fulfilment-onboarding-process)). No source established that Unicommerce, Vinculum or EasyEcom hold a formal Flipkart certification, and EasyEcom's Smart Fulfillment guide asks for a seller username and password in addition to API keys ([EasyEcom](https://support.easyecom.io/portal/en/kb/articles/flipkart-smart-fulfillment)), which hints at panel-level access for that model.

## Myntra and Meesho are gated, and Kartriq's assumed endpoints are not supported

Kartriq's `meesho.js` assumes `supplier.meesho.com/api/v3` with a `meesho-api-key` header, and `myntra.js` assumes `omnishipper.myntra.com/api/v2` with supplierId, apiKey and secretKey. **Neither assumption was verified, and both conflict with what was found.** For Myntra, an official Developer Centre exists with "PPMP API V4" and "Omni API V4" documentation behind a login ([Myntra Developer Centre](https://mmip.myntrainfo.com/), [PPMP V4](https://mmip.myntrainfo.com/documentation/myntra-ppmp-api-v4)). OMS vendors state the credentials are a Merchant Id, Secret Key and Warehouse Id issued by Myntra, with V4 recommended ([Unicommerce](https://support.unicommerce.com/index.php/knowledge-base/myntra-ppmp-integration/)), and the seller must ask their account manager to enable APIs ([Vin e-Retail](https://docs.vineretail.com/myntra-integration/)). The term "omnishipper" appeared in no source. Whether V4 uses any token flow is unknown, since auth details could not be retrieved. So the Myntra adapter is contradicted in part (credential triple, host, version) and unverified in the rest.

What Myntra's PPMP model reportedly requires matters more than the host. Search summaries of the V4 doc say inventory is pushed per facility as absolute numbers including open orders, in batches of 10 per call at 100 requests per minute; the seller must expose an API returning a PDF invoice once shipped status is sent; and the manifest is generated in the seller's system and signed by Myntra's first-mile picker, with the seller keeping a copy ([PPMP V4](https://mmip.myntrainfo.com/documentation/myntra-ppmp-api-v4)). That implies Kartriq must host an invoice-PDF endpoint reachable by Myntra, a real architectural requirement the current adapter lacks. Vinculum's PPMP connector covers order pull, pack with invoice and label generation, shipment, inventory push and reconciliation, pre-fetch and acknowledgement, and notes Myntra has no SKU pull API ([Vinculum](https://vinculumhelpdesk.freshdesk.com/support/solutions/articles/9000198514-myntra-ppmp)). Unicommerce says invoices and labels can be fetched from Myntra but the manifest copy is produced on its side, and it supports separate JIT/SJIT (where cancellation and return are not supported), PPMP and an Enterprise-only PPMP Omni model ([SJIT](https://support.unicommerce.com/index.php/knowledge-base/integration-with-myntra-sjit/)). Myntra's returns and label endpoint paths and its price-update API were not retrieved, and Myntra's seller-model terms (JIT, PPMP, FBM/SOR) are described inconsistently by secondary sources ([Fibre2Fashion](https://emerge.fibre2fashion.com/blogs/11138/myntra-seller-guide-2025-how-fashion-brands-can-win-on-india-s-top-fashion-marketplace)). Kartriq must first pick which model its sellers use.

Meesho has no public developer documentation found. Partners email meesholink-integration@meesho.com with a legal name and contact and receive a unique identifier ([Fynd](https://documentation.fynd.com/konnect/channels/marketplaces-webstores/meesho/register-on-meesho)); Unicommerce says a Merchant Id, Supplier Identifier and Secret are supplied by Meesho ([Unicommerce](https://support.unicommerce.com/index.php/knowledge-base/integration-with-meesho/)). That is a three-part credential, not a single api-key. One unofficial directory, resting on a single search summary, reports signed-request headers and hosts merchant.meesho.com (production) and merchant.meeshotest.in (test) ([API Evangelist](https://providers.apievangelist.com/providers/meesho/)); treat it as a lead only. Capability evidence is partial: Fynd auto-fetches shipments, downloads Meesho-generated labels, builds the invoice and syncs inventory with a buffer ([Fynd](https://documentation.fynd.com/konnect/channels/marketplaces-webstores/meesho)); Unicommerce offers label-only, label-plus-invoice, A6 and A7 options, with the invoice label fetched from the channel only; EasyEcom lists manifest generation for Meesho but calls the API "under development", a possibly outdated article ([EasyEcom](https://support.easyecom.io/portal/en/kb/articles/integrating-meeshoapi-with-easyecom)). Confirm or accept, RTD, manifest, returns and price endpoints for Meesho are unknown. Meesho also arranges couriers itself, with its own Valmo network handling about 50% of orders and later a reported 62% of shipments in a quarter ([Outlook Business](https://www.outlookbusiness.com/start-up/news/ipo-bound-meeshos-own-logistics-platform-valmo-now-handles-50-of-its-orders), [Zerodha Daily Brief](https://thedailybrief.zerodha.com/p/can-shadowfax-deliver)), so Kartriq's own-courier flow (iThink, Shiprocket and others) would not apply there. An unofficial Chrome extension that automates panel label downloads ([Chrome Web Store](https://chromewebstore.google.com/detail/hngplcapocbajnedopnnamgakkdolifi)) shows demand but no OMS vendor documents panel scraping; Kartriq should not depend on it.

## Ajio, Nykaa, Tata CLiQ and JioMart are credential-gated, Shopify is open

Only Shopify offers self-serve API access. Custom-distribution apps need no app review, while public apps and protected customer data do need approval, according to community and third-party pages ([Shopify community](https://community.shopify.dev/t/possible-to-embed-custom-app-without-shopify-app-store/2804), [Stacksync](https://docs.stacksync.com/connectors/shopify/access-protected-customer-data-in-shopify)). Shopify's `fulfillmentCreate` input takes `notifyCustomer` (default false), `trackingCompany` and `trackingNumber`, and docs exist for API versions 2025-10, 2026-04 and 2026-07 ([Shopify docs](https://shopify.dev/docs/api/admin-graphql/2026-04/input-objects/OrderCreateFulfillmentInput)). The fuller flow (query `fulfillmentOrders`, then `fulfillmentCreate`, later `fulfillmentTrackingInfoUpdate`, with scopes such as `write_merchant_managed_fulfillment_orders`) comes from training knowledge, not from any source in this research, and must be checked on shopify.dev before building.

The four Indian marketplaces showed no public developer portal. Ajio issues a POB user ID starting "DV", and separate shipping API access is confirmed with the account manager ([Base](https://base.com/en-EN/help/knowledgebase/ajio-integration-with-base/)); Increff says its Ajio dropship integration uses Ajio's Vendor Management System APIs with the seller sharing panel credentials ([Increff](https://support.increff.com/support/solutions/articles/36000237862-ajio-dropship-via-vms-integration)). Nykaa API username, password and Seller ID come from the Nykaa team ([EasyEcom](https://support.easyecom.io/portal/en/kb/articles/integrating-nykaa-with-easyecom)). Tata CLiQ credentials come from the seller's category manager, with a Slave ID needed by EasyEcom and Vinculum ([Uniware](https://support.unicommerce.com/index.php/knowledge-base/integrating-with-tata-cliq/), [Vinculum](https://docs.vineretail.com/tata-cliq-integration-with-vin-e-retail/)). JioMart credentials and per-warehouse LocationIds come from category managers ([Uniware](https://support.unicommerce.com/?p=9291)), and Jio Commerce publishes a Unicommerce Extension built on v3 Inventory and Order APIs plus an ecosystem page, hinting at a partner-extension programme ([Jio Commerce](https://www.jiocommerce.io/updatelog/unicommerce-extension)).

Competitor coverage is uneven. Unicommerce documents Ajio (JIT, dropship, B2B; manifest PDFs pulled after manifest close; scanning mandatory for picklists; JIT limited to Fashion and Luxury on Professional or Enterprise accounts) ([Uniware Ajio](https://support.unicommerce.com/?p=1269)), Nykaa in several models with Omni gated to Enterprise ([Uniware Nykaa](https://support.unicommerce.com/?p=10366)), Tata CLiQ including Omni, and JioMart with location-wise inventory, order and return sync. Vinculum documents Ajio JIT and Tata CLiQ (order pull, pack with invoice and label, label prefetch, shipment, inventory reconciliation); its JioMart listing was only "Coming soon" ([Jio Commerce](https://www.jiocommerce.io/eco-systems)). EasyEcom documents Nykaa (including a B2B JIT model that can create Ekart shipments), Tata CLiQ, and a JioMart integration announced in April 2023 ([EasyEcom changelog](https://easyecom.io/whatsnew-category/integrations)); no EasyEcom Ajio page was found. Whether a SaaS can obtain these credentials without a commercial agreement is **unknown**; the plausible path, which OMS vendors follow, is each seller requesting credentials from its own manager. Seller-demand data was not found, so any ranking by demand is a hypothesis. By feasibility the notes rank Shopify, JioMart, Tata CLiQ, Nykaa, then Ajio, which is judgement, not evidence.

## What competitors offer beyond Kartriq's scope

The baseline across the Indian vendors is multichannel order pull, inventory sync, courier allocation, labels and manifests, returns, GST invoicing and accounting export, with differentiation in warehouse depth (Vinculum, Increff, EasyEcom, Unicommerce) versus shipping and NDR depth (Shiprocket, Shipway). Concretely, beyond Kartriq's current feature set:

| Capability | Who markets it (grade) |
|---|---|
| E-invoice and e-way bill | EasyEcom via GST Hero for B2B and B2C, with a Failed Order tab for B2C e-invoice failures, ship-to GSTIN mapping and TCS calculation ([EasyEcom](https://support.easyecom.io/portal/en/kb/articles/generating-einvoice-and-ewaybill-for-b2b-orders)); not found for Unicommerce, Vinculum or Increff |
| Tally and accounting | Unicommerce (Tally GST return, cancel and reconciliation reports, tax-verification column flagging rate mismatches vs marketplace invoice) ([Unicommerce](https://www.unicommerce.com/accounting/)); EasyEcom posts vouchers with IRN, ack date, e-way bill number ([EasyEcom](https://www.easyecom.io/integrations/tally-integration)) |
| Multi-marketplace manifests | EasyEcom bulk dispatch ([EasyEcom](https://easyecom.io/whatsnew-articles/ui-enhancement-faster-bulk-dispatch-with-multi-marketplace-manifests)) |
| Settlement and payment reconciliation | EasyEcom claims it; depth per marketplace not found |
| WMS depth (bins, serials, vendors, routing) | EasyEcom, Increff (order routing and splitting, serialized inventory), Browntape (pick-and-pack, batches) |
| Omnichannel store fulfilment | Vinculum (BOPIS, return-in-store, store apps), Increff (store fulfilment and O2O) |
| NDR and RTO tooling, courier ranking | Shiprocket (NDR panel, RTO dashboard, CORE recommendation) and Shipway (NDR, WhatsApp tracking) — vendor claims ([Shiprocket](https://www.shiprocket.in/blog/pickrr-vs-shiprocket/amp), [Shipway](https://blog.shipway.com/?p=66923)) |

Among global tools, Linnworks is described by a competitor blog as having a carrier rules engine, label automation and rate shopping ([getonecart](https://www.getonecart.com/linnworks-alternatives/)); Zoho with Shiprocket fetches live multi-carrier rates and labels in-app ([Zoho](https://www.zoho.com/in/inventory/shiprocket-integration/)); Extensiv markets SKU-level profitability, FIFO costing, inventory ageing, demand planning and PO-level COGS ([Extensiv](https://www.extensiv.com/amazon-fba-inventory-order-management-software)); Cin7 Omni bundles EDI, POS and 3PL ([eightx](https://eightx.co/blog/compare/how-much-does-cin7-cost)). Returns, RMA, listing and repricing depth could not be sourced for any global vendor, and Rithum's post-2022 scope was not retrieved. On Amazon-arranged shipping, no source documented Buy Shipping or Easy Ship label flows for any of the six global vendors; Zoho's help only states that FBM sellers handle shipping themselves ([Zoho](https://www.zoho.com/ae/inventory/help/marketplaces/amazon.md)). That Kartriq's Amazon flow is a differentiator is therefore an **inference from absence of evidence**, not a finding.

On trust and security, Cin7 announced SOC 2 Type 1 and Type 2 in February 2025 ([Cin7](https://www.cin7.com/blog/cin7-achieves-soc-2-type-1-and-type-2-compliance/)), and Linnworks claims ISO 27001, AES-256, TLS 1.2+ and mandatory MFA for admin platforms ([Linnworks](https://www.linnworks.com/security/)); Unicommerce claims ISO 27001 and 27701 ([Capterra](https://www.capterra.in/software/136123/unicommerce)). Kartriq's admin MFA, PII audit log, 30-day buyer-data purge and buyer-data export permission are comparable controls, but no competitor's audit-log or role model was found, so no claim of superiority is supportable. Pricing is unreliable: EasyEcom charges per order on recharge slabs ([EasyEcom](https://support.easyecom.io/portal/en/kb/articles/easyecom-pricing)) and Unicommerce is usage-based and prepaid with no official price page found; Browntape sources conflict (Rs 5,000 minimum recharge versus other figures); Zoho India reseller prices conflict with USD list tiers; Cin7, Linnworks and Brightpearl are quote-based or third-party estimated. Kartriq's unlimited-user, no-usage-limit plan is a possible positioning angle, but no verified competitor price exists to compare against. Review evidence is small and dated (Unicommerce 4.3/5 on 114 Capterra reviews, with complaints about a dated UI, learning curve and slow tickets; Shiprocket complaints on weight disputes and COD remittance delays) ([Capterra](https://www.capterra.ca/reviews/136123/unicommerce), [Capterra](https://www.capterra.com/p/159386/Shiprocket/reviews)).

## A prioritised roadmap, gated on credentials and live tests

The sequence below follows from the evidence: build where an official API is documented, and spend human effort first on the unlocks that gate everything else. Priorities are judgement; the notes contain no seller-demand data.

First, in the next weeks and in parallel with engineering: a human must raise the Flipkart sandbox ticket, request Meesho's spec and credentials from the integration team, and obtain Myntra V4 documentation and credentials through a Myntra-onboarded seller's account manager. Until these arrive, the Meesho and Myntra adapters should be flagged in the product as unverified rather than shipped as live.

Second, rebuild Flipkart as a full flow mirroring the Amazon pattern: shipment filter, label (pack), dispatch and manifest, with per-tenant Application ID, Secret and location ID, the Standard versus Self Ship choice, and sandbox testing before go-live. This is the highest-value, best-documented item and reuses Kartriq's label, bulk-label and packing-slip machinery. Add returns only after the endpoints are found.

Third, Myntra PPMP on V4 once docs arrive, including a hosted invoice-PDF endpoint, a seller-side manifest copy, per-facility absolute inventory pushes within the 100 requests per minute and 10-per-batch limits, and an explicit decision on which Myntra models (PPMP, JIT/SJIT, Omni) to support. Fourth, Meesho on the partner spec: label download from Meesho, inventory with buffer, and manifest only if the spec confirms it. Fifth, Shopify fulfilment write-back (fulfillmentOrders, tracking, notify flag) after verifying scopes on shopify.dev, since it is open and self-testable and needs no gatekeeper.

Sixth, the compliance and finance layer that the Indian incumbents sell: GST e-invoice and e-way bill, Tally voucher export, and per-marketplace settlement reconciliation with a tax-mismatch check. Seventh, shipping intelligence: courier rate shopping and rules across the already-integrated couriers, plus NDR and RTO handling, borrowing from Shiprocket, Shipway and Linnworks. Eighth, SKU and order profitability with marketplace fees, shipping, returns and GST, plus PO costing and reorder reports, borrowing from Extensiv. Ajio, Nykaa, Tata CLiQ and JioMart come after, starting with JioMart (a partner-extension programme exists) and Tata CLiQ, and only where an early customer can supply credentials; Increff's and Unicommerce's guidance suggests several are multi-model and some Enterprise-gated, so each is a project. Defer EDI, enterprise dropship networks (Rithum-style) and store-fulfilment (BOPIS) as poor early ROI. A SOC 2 or ISO 27001 effort is a reasonable medium-term trust investment given Cin7, Linnworks and Unicommerce publish them.

## Conclusion

The research changes the framing of Kartriq's gap. The competitors' advantage is less about feature count than about access: Myntra, Meesho and the four gated marketplaces all hand credentials out through account or integration managers, so incumbents such as Unicommerce, whose Tata CLiQ tie-up dates to 2018 ([YourStory](https://ts.yourstory.com/2018/01/tata-groups-tatacliq-ties-up-with-unicommerce-for-omnichannel)), hold relationship moats that code alone cannot cross. Flipkart is the exception and the right first bet, because its documented API lets Kartriq reach parity on dispatch, label and manifest without waiting on anyone except a sandbox ticket.

The second implication is that two existing adapters may be worse than missing, since they rest on guessed hosts and credentials that the available evidence contradicts. Shipping them as live invites support burden and sellers' trust problems. The Indian-market features that remain after fulfilment parity, namely GST e-invoicing, Tally and reconciliation, are where sellers' daily accounting pain sits and where Kartriq's existing buyer-data and security controls give it a credible, if unquantified, trust story. All of this should be re-ranked as soon as a human has read the live Flipkart, Myntra and Meesho documentation.
