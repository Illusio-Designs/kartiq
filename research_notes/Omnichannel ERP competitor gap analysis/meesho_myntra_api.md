# Meesho and Myntra seller integration/API options

Method note: only search-result summaries were obtainable. Direct page fetches failed (DNS errors and proxy policy 403 for support.unicommerce.com, mmip.myntrainfo.com, documentation.fynd.com, etc.). Findings below are from search-tool summaries of those pages, not from reading full pages. Endpoint-level detail for Meesho and Myntra's V4 API could not be retrieved.

## Does an official public API exist, and how is access obtained (Meesho and Myntra)?

### Takeaway
Neither is a self-service public API. Meesho: partner-gated; credentials are issued by Meesho's integration team after an email request, and no public docs were found. Myntra: an official developer centre with versioned docs exists (PPMP API V4, Omni API V4 at mmip.myntrainfo.com), but credentials (Merchant Id, Secret Key, Warehouse Id) come from the Myntra account manager/team after they enable APIs for the seller.

### Cited Findings
- No public, official Meesho developer documentation was found; search results point to a partner-gated API, credentials via Meesho's integration team — [Fynd Konnect register-on-Meesho guide](https://documentation.fynd.com/konnect/channels/marketplaces-webstores/meesho/register-on-meesho) (partners email meesholink-integration@meesho.com with legal name and contact; a unique identifier per location is shared); [Unicommerce Meesho](https://support.unicommerce.com/index.php/knowledge-base/integration-with-meesho/) (Merchant Id, Supplier Identifier and Secret are provided by the Meesho team).
- EasyEcom's Meesho-API flow: add channel "Meesho-API", enter Meesho username, then email Meesho's integration team with registered Meesho email and the EasyEcom unique identifier; article says Meesho's API is "under development" and Invoice Amount Details are not available (possibly outdated) — [EasyEcom](https://support.easyecom.io/portal/en/kb/articles/integrating-meeshoapi-with-easyecom)
- One third-party directory describes the Meesho API as signed-request-header auth with hosts merchant.meesho.com (prod) and merchant.meeshotest.in (test). UNOFFICIAL, single secondary source (search summary of [API Evangelist](https://providers.apievangelist.com/providers/meesho/)); not confirmed by an OMS vendor or Meesho.
- Zoho Inventory states it has no direct Meesho integration — [Zoho](https://www.zoho.com/in/inventory/kb/general-overview/meesho.html)
- Myntra has an official Developer Centre with "PPMP API V4" and "Omni API V4" docs (login/sign-up) — [Myntra Developer Centre](https://mmip.myntrainfo.com/), [PPMP API V4](https://mmip.myntrainfo.com/documentation/myntra-ppmp-api-v4), [Omni API V4](https://mmip.myntrainfo.com/documentation)
- Myntra credentials: Merchant Id, Secret Key and Warehouse Id obtained from Myntra team; API version V4 recommended — [Unicommerce Myntra PPMP](https://support.unicommerce.com/index.php/knowledge-base/myntra-ppmp-integration/), [Unicommerce PPMP Omni](https://support.unicommerce.com/index.php/knowledge-base/integration-with-myntra-ppmp-omni/)
- Seller must contact account manager to enable APIs — [Vin e-Retail Myntra PPMP](https://docs.vineretail.com/myntra-integration/)
- Models Unicommerce supports for Myntra: JIT/SJIT, PPMP (dropship-style), PPMP Omni (multi-store, Enterprise tenants only) — [Unicommerce SJIT](https://support.unicommerce.com/index.php/knowledge-base/integration-with-myntra-sjit/), [PPMP Omni](https://support.unicommerce.com/index.php/knowledge-base/integration-with-myntra-ppmp-omni/)

### Inferences
- Kartriq's "apply at supplier.meesho.com" is directionally right (approval needed) but the real route is emailing Meesho's integration team, not a panel self-serve key.
- Myntra access is realistic only with a Myntra-onboarded seller and account-manager enablement; a third-party SaaS likely needs the seller to obtain credentials per account.

### Gaps
- Authentication mechanism (header names, token exchange) for Meesho and for Myntra V4 not retrievable. Whether Myntra V4 uses a supplierId/apiKey/secretKey token flow is unknown.
- Whether Meesho or Myntra run a formal ISV partner programme for new vendors was not found.

## Order workflow capabilities: what software can do vs panel only

### Takeaway
Myntra PPMP: software can pull orders, pack, generate/fetch invoice and label, push inventory, ack/status. Manifest is generated by the seller's system and signed at pickup. Meesho (via API partners): order fetch, label download from Meesho, inventory sync; confirm/manifest not verified.

### Cited Findings
- Meesho via Fynd: auto-fetches new shipments, downloads shipping labels from Meesho's API, generates customer invoice in Fynd from Meesho data; inventory sync with buffer; mapping via CSV/XLSX; no manifest documentation found — [Fynd Meesho channel](https://documentation.fynd.com/konnect/channels/marketplaces-webstores/meesho), [configure](https://documentation.fynd.com/konnect/channels/marketplaces-webstores/meesho/configure-on-konnect), [product mapping](https://documentation.fynd.com/konnect/channels/marketplaces-webstores/meesho/product-mapping)
- Unicommerce Meesho: label options (label-only, label+invoice, A6/A7); label with invoice is fetched from the channel only — [Unicommerce Meesho](https://support.unicommerce.com/index.php/knowledge-base/integration-with-meesho/)
- EasyEcom lists "Manifest Generation" as a feature of its Meesho integration (via search summary) — [EasyEcom](https://support.easyecom.io/portal/en/kb/articles/integrating-meeshoapi-with-easyecom)
- Meesho seller flow (guides, secondary): order notification, pack, download label (and manifest) from supplier panel, courier collects — [Auto Label Downloader extension listing](https://chromewebstore.google.com/detail/hngplcapocbajnedopnnamgakkdolifi) (UNOFFICIAL third-party Chrome extension that automates accepting orders and downloading Ready-to-Ship labels from the panel, which suggests panel automation exists as a workaround), [Startuptalky](https://startuptalky.com/meesho-seller-guide/)
- Myntra PPMP V4 doc points (search summary): inventory pushed per facility as absolute numbers including open orders, batch of 10 per call, 100 requests/minute; seller must provide an API returning a PDF invoice once shipped status is sent; manifest generated in seller system and signed by Myntra's first-mile picker, seller keeps copy — [PPMP API V4](https://mmip.myntrainfo.com/documentation/myntra-ppmp-api-v4)
- Vinculum PPMP: order pull, pack/invoice/label generation, shipment, inventory push and reconciliation, order pre-fetch, acknowledgement; no SKU pull because Myntra has no API for it — [Vinculum](https://vinculumhelpdesk.freshdesk.com/support/solutions/articles/9000198514-myntra-ppmp), [Vin e-Retail](https://docs.vineretail.com/myntra-integration/)
- Unicommerce PPMP: inventory push, invoice details sync, order status sync, catalog sync; invoices/labels can be fetched from Myntra but manifest copy generated on Uniware side; orders sync only after listing mapping — [Unicommerce PPMP](https://support.unicommerce.com/index.php/knowledge-base/myntra-ppmp-integration/)
- Unicommerce Myntra JIT/SJIT: order cancellation and return not supported; invoices and labels generated on Uniware side — [Unicommerce SJIT](https://support.unicommerce.com/index.php/knowledge-base/integration-with-myntra-sjit/)
- Base: auto labels/invoices after shipment creation; near-real-time inventory using webhook token shared with Myntra — [Base](https://base.com/en-EN/help/knowledgebase/myntra-ppmp-integration-guide-for-base/)
- Increff lists Myntra and Meesho among marketplace integrations; method not stated in results — [Increff](https://www.increff.com/market-places)

### Inferences
- Pattern across vendors: API/partner credentials for both, not CSV scraping; CSV/XLSX is used for SKU mapping (Fynd). Panel scraping is not documented by any OMS vendor found.
- Meesho "confirm/accept" step not documented as API-capable; treat as unverified.

### Gaps
- Meesho endpoints for confirm/RTD/manifest, returns/RTO, price updates: not found.
- Myntra price update API, returns endpoint paths, label endpoint paths: not retrieved.
- How Increff integrates: not found.

## Logistics and per-order seller actions

### Takeaway
Meesho: Meesho arranges couriers (in-house Valmo plus Shadowfax, Delhivery, Xpressbees etc.); seller packs, pastes label, courier picks up. Myntra: PPMP = seller holds stock, marketplace-provided courier; JIT = Myntra issues PO, seller ships to Myntra hub; FBM/SOR = stock at Myntra warehouse.

### Cited Findings
- Valmo handled ~50% of Meesho orders (later report ~62% of shipments in quarter ended June 2025); Meesho says it continues to use Delhivery, Shadowfax, Xpressbees, Ecom Express — [Outlook Business](https://www.outlookbusiness.com/start-up/news/ipo-bound-meeshos-own-logistics-platform-valmo-now-handles-50-of-its-orders), [Zerodha Daily Brief](https://thedailybrief.zerodha.com/p/can-shadowfax-deliver)
- Seller per-order on Meesho (secondary guides): pack, download label, stick on package, courier partner picks up — [Startuptalky](https://startuptalky.com/meesho-seller-guide/)
- Myntra models (secondary): JIT = bulk PO to seller then sorted at Myntra hub; PPMP = seller holds stock, courier provided by marketplace, returns to seller warehouse; FBM described as Fulfillment by Myntra/"SOR - Sale or Return" (sources inconsistent) — [Shiprocket Fulfillment on Myntra logistics](https://fulfillment.shiprocket.in/blog/inside-myntras-logistics/), [Fibre2Fashion](https://emerge.fibre2fashion.com/blogs/11138/myntra-seller-guide-2025-how-fashion-brands-can-win-on-india-s-top-fashion-marketplace)
- Partner Portal is Myntra's seller panel (registration, M-Direct path under Order Fulfillment) — same Fibre2Fashion source.

### Gaps
- No reliable source defining "SJIT" beyond Unicommerce's connector name; Valmo-specific panel steps; Myntra returns flow details; "omnishipper" not found in any source.

## Verification of Kartriq's assumed endpoints

### Takeaway
Neither assumed endpoint is verified. Meesho's `supplier.meesho.com/api/v3` + `meesho-api-key` and Myntra's `omnishipper.myntra.com/api/v2` supplierId/apiKey/secretKey flow found no supporting source. Partially contradicted: Myntra's real API docs are at mmip.myntrainfo.com with V4 versions and Merchant Id/Secret Key/Warehouse Id credentials; the term "omnishipper" returned no hits.

### Cited Findings
- Code location: `backend/src/services/channels/ecom/meesho.js` (BASE supplier.meesho.com/api/v3, header `meesho-api-key`), `myntra.js` (omnishipper.myntra.com/api/v2), `config/channel-endpoints.js` lines 144-145, `data/channel-catalog.js` docsUrl `https://supplier.meesho.com/api` (local repo).
- Meesho credentials per OMS vendors are Merchant Id + Supplier Identifier + Secret, not a single api-key — [Unicommerce Meesho](https://support.unicommerce.com/index.php/knowledge-base/integration-with-meesho/); unofficial directory suggests hosts merchant.meesho.com / merchant.meeshotest.in with signed headers — [API Evangelist](https://providers.apievangelist.com/providers/meesho/) (unofficial)
- Myntra V4 versioning and Merchant Id/Secret Key/Warehouse Id — see sources above.

### Inferences
- Meesho: UNVERIFIED, likely contradicted (different credential model and host reported).
- Myntra: UNVERIFIED for omnishipper/v2; CONTRADICTED in part by official V4 docs and credential triple. Recommend rebuilding against mmip.myntrainfo.com V4 after obtaining docs via a Myntra-onboarded seller account, and requesting the Meesho spec from the integration team.

- Could not read Myntra developer docs or Meesho spec directly; a human with network access/login should confirm.
